# Swift App Roadmap

**A template for building a SwiftUI app, and its website if it needs one,
with AI agents, from an idea to version 1.0 in the App Store.**

Clone it, start an AI agent session inside it, and describe the app you
want. The agent researches the idea, interviews you about every decision
that shapes the product, and rewrites three files into a complete plan:

- **[BUILD.md](BUILD.md)**: the master plan. What the finished product is,
  your decisions, the engineering foundations, and ordered phases of small,
  verifiable checkbox items (`P4.3`) from an empty repository to the 1.0
  launch, ending in handoff notes for the next session.
- **[AGENTS.md](AGENTS.md)**: how every agent session works. Git rules,
  the session loop, the product's voice and conduct, who decides what,
  stack rules, the definition of done, and commits.
- **README.md** (this file): the product's own introduction, status,
  architecture, layout, prerequisites, and quick start.

After that, every session follows the same loop: read AGENTS.md and
BUILD.md, take the first open item, build it, verify it, tick it in the
same commit, and leave handoff notes. Progress is visible in BUILD.md's
Build status table at any moment, and finished phases move to
BUILD-HISTORY.md so the plan stays short enough to read in one sitting.

### How to use it

1. **Make it yours.** Create an empty repository for your product, then
   clone this template and point `origin` at your repository (or use
   GitHub's "Use this template"). The setup agent checks this and will not
   push your product to the template.
2. **Start an agent session** in the repository (Claude Code, Codex, or any
   agent that reads `AGENTS.md`; `CLAUDE.md` imports it for Claude Code).
3. **Describe your app.** Paste your idea, from a paragraph to a full
   specification, for example:

   > Set up this template for my app. Here is the idea: …

4. **Answer the interview.** The agent asks about name and identifiers,
   platforms and stack (app only, app and site, or app and web app),
   accounts, privacy, pricing, analytics, AI, the visual design, hosting,
   and the questions your product raises, each with a recommended answer.
5. **Review the plan** it writes, ask for changes, and let it commit.
6. **Build.** In each new session, say:

   > Read AGENTS.md and continue the build.

   Take care of the steps marked **[OWNER]** when the agent asks: creating
   accounts, signing in to Xcode, choosing the design. Everything else the
   agents do.

### The defaults it plans for

A native SwiftUI app (iPhone and iPad first) in Swift 6 with strict
concurrency; shared Swift packages holding the product's rules, specified in
a document and pinned by table-driven tests; an Xcode project generated by
XcodeGen; one `make check` gate before every commit and `make check-full` at
milestones; a TestFlight path from the first phase; a design session where
you choose among three visual directions before anything is built on top
of them; and, if the product has one, a website or web app served by a
Swift server that shares the same packages. Privacy, accessibility, and
honesty in the interface are part of the definition of done. Every default
is a decision you can change in the interview.

### The reference project

[Day by Word](https://github.com/dunamismax/daybyword) was planned and is
being built exactly this way: a SwiftUI app and a Hummingbird web app
sharing one Swift engine. Its BUILD.md, AGENTS.md, and BUILD-HISTORY.md
show what the template becomes in practice.

The template itself is MIT-licensed (`LICENSE`); the setup replaces the
licence with the one you choose for your product.

## Quick start

From a clean checkout:

```sh
make check       # lint and every test: the gate before every commit
make check-full  # check, the tours in light and dark, and every platform: at milestones and before releases
make run         # build, boot the newest iPhone simulator, install, and launch the app
make serve       # serve the site at http://localhost:8080 (server variants only)
```

`make help` lists every target. {{OTHER_TARGETS_WORTH_KNOWING}} Set
`SIM_DEVICE` to a simulator's name or UDID to choose a device.
